Configure each machine once. From then on squirrel's [agent](/squirrel/guides/agent/)
owns the loop: indexing, syncing, verification, snapshots, and durability
exchange all happen on their own cadences. A correct setup goes months without
anyone typing a command — and loses nothing.

## Why squirrel

<CardGrid stagger>
  <Card title="Set up once, then trust" icon="rocket">
    Install and configure a machine once. The agent handles indexing, syncing,
    verification and evidence exchange on their cadences. Every command squirrel
    has is either a deliberate change or a question you asked — never a chore it
    should have done for you.
  </Card>
  <Card title="One glance, one answer" icon="magnifier">
    [`squirrel status`](/squirrel/reference/cli/#squirrel-status) and the
    [TUI](/squirrel/guides/tui/) answer "am I safe?" for a volume everywhere it
    lives — every destination and every other machine: whether each is caught
    up, how far behind it is, whether it is durable, and when its evidence was
    last actually *verified*. Green means you can close the laptop. Anything
    else says what to do about it — and says it until you deal with it, because
    alarms latch instead of scrolling away.
  </Card>
  <Card title="Verified, not assumed" icon="approve-check">
    Every upload is checked against what actually landed, and offsite copies are
    [re-checked](/squirrel/guides/verification/) on their own schedule long
    after the transfer succeeded. "The upload didn't error" is not evidence; a
    fingerprint that still matches months later is. When a check fails, squirrel
    says so and keeps saying so.
  </Card>
  <Card title="Deleting locally never deletes the copy" icon="laptop">
    Squirrel never propagates a delete. Removing a file locally leaves every
    durable copy exactly where it is, and a destination keeps content the source
    no longer has. That is what makes freeing up space safe:
    [`squirrel offload`](/squirrel/guides/offloading/) removes local bytes *on
    purpose*, and only once the content is verified on every destination you
    required. Old photos leave your laptop; they don't leave your archive.
  </Card>
  <Card title="Nothing is ever lost" icon="document">
    Content is addressed by BLAKE3, so a hash ever observed stays
    [retrievable](/squirrel/start/principle/). Destinations are append-only — an
    overwrite preserves the prior bytes. Both sides of a sync conflict survive.
    The [audit trail](/squirrel/concepts/runs/) is never auto-pruned. This is
    the floor everything else stands on.
  </Card>
</CardGrid>

## From one computer to every device you own

Squirrel works the same at any size: one machine backing up to one destination,
or many machines sharing several — local drives, network storage, cloud buckets,
cold archive. Same config file, same commands. Add machines and destinations as
you get them.

## Under the hood

How the guarantees above are enforced, one layer down.

<CardGrid>
  <Card title="Content, not paths" icon="approve-check-circle">
    A BLAKE3 hash that has ever been observed stays retrievable. Paths are
    observations of content, not the other way around — `squirrel query <hash>`
    still finds a hash whose path now holds different content.
  </Card>
  <Card title="Verified uploads" icon="seti:lock">
    Sync verifies each uploaded file's BLAKE3 against the destination. Encrypted
    remotes fall back to size+mtime, and cold-archive tiers get a metadata-only
    scan-back fingerprint check that never re-downloads a byte.
  </Card>
  <Card title="Append-only by design" icon="seti:folder">
    Overwrites are preserved under `.squirrel-history/`, and sync never deletes
    at the destination even when the local copy is gone. History is an audit
    trail, never auto-pruned.
  </Card>
  <Card title="Many backends, one config" icon="setting">
    Mirror, encrypted, kopia, content-addressed, and packed layouts across
    local, sftp, s3, b2, and gcs — all declared in one TOML file. Squirrel owns
    the [rclone](https://rclone.org) command line so you never run
    `rclone config`.
  </Card>
</CardGrid>
